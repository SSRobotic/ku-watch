# KU Watch — เปิดจอก่อน

เวอร์ชัน 2.0.0 • 8 ตุลาคม 2569 • PlatformIO / ESP32-S3 Super Mini / GC9A01(A) 240×240

เพิ่มหน้า MAP แทน GPS พร้อมแผนที่จริงบางเขนแบบออฟไลน์และเส้นกิจกรรมที่บันทึกจาก GPS ใช้ PSRAM 2 MB ของบอร์ดสำหรับภาพจอและแผนที่ ดู [วิธีใช้แผนที่](ใช้แผนที่_MAP.md) ยืนยันแผนที่อำนาจเจริญแล้ว ผู้ใช้ยืนยัน GPS FIX; การเดินตรวจความแม่นยำยังเลื่อนไว้ตามผู้ใช้

## อัปเดตการใช้อุปกรณ์

- ยกเลิกโมดูล SD เดิมแล้ว ทั้ง `src/main.cpp` และ `src/display_test.cpp` ไม่กำหนด GPIO13 เป็นขา CS ของ SD อีก ไม่มีการอ่านหรือเขียน SD ในโปรเจกต์นี้
- เพิ่มชื่อบอร์ด `ESP32-S3-Touch-LCD-2.1` ตามที่ผู้ใช้แจ้ง โดยมีแผนเชื่อมกับ Super Mini ผ่าน ESP-NOW แบบรับ–ส่งสองทาง ขณะนี้บันทึกการเปลี่ยนอุปกรณ์เท่านั้น ยังไม่พัฒนา ESP-NOW หรือเฟิร์มแวร์บอร์ดจอใหม่
- แบตเตอรี่ล่าสุดที่ผู้ใช้ระบุเป็น LiPo 3.7 V ความจุ **1000 mAh** สายไฟ 3 เส้น ตามลิงก์สินค้า ยังไม่ยืนยันหน้าที่สายที่สาม
- เพิ่มโมดูล GPS/BeiDou `ATGM336H` พร้อมเสาอากาศ จำนวน 1 ชุด ตามรายการในภาพ (ชื่อประกาศระบุใช้แทน NEO-M8N ไม่ได้ระบุว่าโมดูลที่ซื้อเป็น NEO-M8N)
- เพิ่มโค้ด GPS ผ่าน UART1 แล้ว: GPS TX → GPIO12, GPS RX → GPIO13; ดูไฟเลี้ยงและรายละเอียดใน [คู่มือต่อสาย](ต่อสาย_GPS_MAX30102.md)
- MAX30102 สีดำตามภาพใช้ VIN→3V3, GND→GND, SDA→GPIO8, SCL→GPIO9; ใช้แทนตัวเดิมหากมี MAX30102 ต่ออยู่แล้ว
- พบ INA226 ที่ 0x44 และแก้โค้ดอ่านแรงดัน/ประมาณเปอร์เซ็นต์ให้ตรงแล้ว โมดูลมีขา VBS สำหรับวัดแบต วงจรจ่ายไฟจากแบตผ่านสวิตช์และขั้วสายแบตยังรอยืนยัน

แบบวงจร KiCad 10.0 อยู่ที่ [hardware/KU_Watch/KU_Watch.kicad_pro](hardware/KU_Watch/KU_Watch.kicad_pro) พร้อม [คำอธิบายแบบภาษาไทย](hardware/KU_Watch/README_TH.md) ผู้ใช้ยืนยันให้ GPS และแบตเตอรี่อยู่ฝั่ง Super Mini เฟิร์มแวร์ 1.1.0 ใช้ขารับของ ESP32 ที่ GPIO12 และขาส่งที่ GPIO13 ตรงกับแบบ ส่วนวงจรจ่ายไฟจากแบตเตอรี่ยังรอระบุอุปกรณ์และขั้วสาย

**พินที่แก้ตามสายจริง:** ผู้ใช้ยืนยันว่า **DC ต่อ GPIO7 และ CS ต่อ GPIO6** รุ่น 1.0.1 แก้ตรงกันทั้งหน้าปัด `display_first` และโปรแกรมทดสอบ `display_test` แล้ว ไม่ต้องสลับสายจอเพื่อให้ตรงกับคู่มือเก่า ดู [บันทึกการตรวจจอขาว](ตรวจจอขาว.md)

อัปโหลดหน้าปัดรุ่น 1.0.1 กลับลง COM15 แล้ว ตั้งเวลาจากคอมสำเร็จ และบอร์ดตอบ `CS=6 DC=7 BME=live` ทาง USB ส่วนภาพจริงยังรอผู้ใช้ยืนยัน

3. **ถอดลำโพงเปล่าจาก GPIO2 ก่อน** ใช้ USB-C ของ Super Mini จ่ายไฟทดสอบ เลือกพอร์ต USB ของบอร์ดตัวเล็ก
4. กด **Build** แล้ว **Upload** เมื่อสำเร็จจอจะขึ้นสีแดง/เขียว/น้ำเงินสั้น ๆ แล้วแสดงหน้าปัด KU
5. กดปุ่ม GPIO4 เพื่อเปลี่ยนหน้า ถ้าต้องดูข้อความตรวจอุปกรณ์ ให้เปิด **Monitor** ที่ 115200

การ Upload เปลี่ยนโปรแกรมบนบอร์ดที่เลือก จึงเลือก Super Mini ตัวเล็กให้ถูกตัว ไม่ใช้โปรเจกต์นี้กับบอร์ด Waveshare 2.1 นิ้ว

## พินในรุ่นนี้

ตัวเลขเป็น **GPIO ที่พิมพ์บนบอร์ด** ไม่ใช่ตำแหน่งรูนับจากมุม

| จอ GC9A01 | ESP32-S3 Super Mini |
|---|---|
| SCL / SCK / CLK | GPIO10 |
| SDA / DIN / MOSI | GPIO11 |
| CS | GPIO6 |
| DC | GPIO7 |
| RST / RES | GPIO5 |
| GND | GND |
| VCC | 3V3 เมื่อโมดูลจอรับ 3.3 V ตามสเปก |
| BL / BLK ถ้ามี | ตามวงจรโมดูลจอ; ถ้าระบุรับไฟ 3.3 V ให้ต่อ 3V3 ไม่ใช้ GPIO2 |

SCL/SDA บนจอเป็นสัญญาณ SPI ไม่ใช่บัส I²C ของเซ็นเซอร์

| อุปกรณ์ | การต่อ |
|---|---|
| ปุ่มเลือกเมนู | GPIO4 ↔ ปุ่ม ↔ GND; โค้ดใช้ INPUT_PULLUP |
| GPIO2 | สำรองสัญญาณเสียงเข้าวงจรขับ ตั้งเป็น input เมื่อเสียงยังปิด |
| เซ็นเซอร์ I2C SDA ทั้งหมด | GPIO8 |
| เซ็นเซอร์ I2C SCL ทั้งหมด | GPIO9 |
| เซ็นเซอร์ GND ทั้งหมด | GND ร่วม |
| BME680 VCC / CS / SDO | VCC→3V3, CS→3V3, SDO→GND เพื่อเลือก 0x76; โค้ดลอง 0x77 ได้ด้วย |

GPIO2 เปลี่ยนจากปุ่ม NEXT ในโปรเจกต์เก่าเป็นสัญญาณเสียงแล้ว อย่าต่อปุ่มเก่าบนขานี้ค้างไว้ GPIO4 ใช้เป็นปุ่มเมนูในรุ่นนี้

## การกดปุ่ม

- **กดสั้นแล้วปล่อย:** หน้าปัด → Environment → Devices → Heart Rate → Motion → Network → MAP → WALK → Air Quality → Battery → ROBOT → หน้าปัด
- **กดสั้นสองครั้งติดกัน:** หน้า MAP วน AUTO → บางเขน → อำนาจเจริญ; หน้า ROBOT วนท่าเล่น ใช้ปุ่ม GPIO4 เดิมปุ่มเดียว ทั้งสองหน้านี้กดหนึ่งครั้งจะรอ 0.45 วินาทีก่อนเปลี่ยนหน้า
- **กดค้าง 0.7 วินาที:** หน้า MAP ใช้ซูม; หน้า WALK ใช้เริ่ม/หยุดบันทึก; หน้า ROBOT ให้อาหาร; หน้าอื่นกลับหน้าปัด เมื่อปล่อยจะไม่เลื่อนไปหน้าอื่นซ้ำ
- เมื่อมีวงจรขับเสียงและเปิดใช้เสียงแล้ว จะมีเสียงสั้นเมื่อเริ่มกด และเสียงอีกโทนเมื่อกดค้างกลับหน้าปัด

หน้าปัดแสดงเวลา วันที่ อุณหภูมิ และความชื้น หน้า Environment เพิ่มความดันอากาศ ส่วน Devices ตรวจการตอบรับที่อยู่ I²C ของอุปกรณ์ที่ต่อไว้ คำว่า ACK หมายถึงมีอุปกรณ์ตอบที่อยู่นั้น ยังไม่ใช่การยืนยันรุ่นหรือผลการวัดของ MAX30102 / INA226 / GY-51

## หน้าจอและเครือข่าย

กดปุ่มสั้นเพื่อวน 11 หน้า: หน้าปัด, Environment, Devices, Heart Rate, Motion, Network, MAP, WALK, Air Quality, Battery และ ROBOT หน้า Heart Rate เพิ่ม SpO₂; หน้าปัดหลักเพิ่มเปอร์เซ็นต์แบตแบบประมาณ

รุ่น 1.3.0 ใช้ MQTT ส่งข้อมูลสดไป Node-RED จากนั้น Node-RED เขียน InfluxDB 3 ฐาน `iot` ตาราง `ku_watch` ให้ Grafana อ่านได้ ตั้งค่า HiveMQ Cloud ด้วย `ตั้งค่า_HiveMQ_Cloud.cmd` และดูรายละเอียดใน [คู่มือ HiveMQ](ใช้_HiveMQ_NodeRED_Grafana.md)

ตั้งชื่อและรหัส Wi-Fi ของบอร์ดใน `include/config.h` ข้อมูลการเชื่อม HiveMQ เก็บแยกในไฟล์ส่วนตัว และต้องอัปโหลดใหม่หลังเปลี่ยนค่า

## เวลา

เมื่อเปิดเครื่อง โปรแกรมเริ่มนับจากเวลา Build และขึ้นคำว่า **BUILD TIME** จึงเห็นตัวเลขเดินได้ทันที แต่หลังถอดไฟแล้วเปิดใหม่จะกลับไปเริ่มจากเวลา Build อีกครั้ง

ถ้าต้องการเวลาปัจจุบัน ปิด Serial Monitor แล้วเปิด Terminal ในโฟลเดอร์โปรเจกต์:

```powershell
py -m pip install pyserial
py tools/set_time.py --port COM15
```

เปลี่ยน COM15 เป็นพอร์ตของตัวเล็กที่ใช้อยู่ โปรแกรมจะรับเวลาจากคอมและแสดงตามประเทศไทย UTC+7 พร้อมเปลี่ยนป้ายเป็น **USB TIME** ต้องตั้งใหม่หลังรีเซ็ต/ถอดไฟ หรือรอ GPS จับพิกัดพร้อมวันเวลาที่ใช้ได้ รุ่น 1.2.0 จะตั้งเวลาจาก GPS อัตโนมัติและแสดง GPS TIME; รุ่น 1.3.0 เพิ่มการตั้งเวลาผ่านอินเทอร์เน็ตอัตโนมัติ (NET TIME) และเริ่ม WALK ได้เมื่อเวลายืนยันจาก USB/GPS/อินเทอร์เน็ตแล้ว

## ลำโพงสองสายที่มีอยู่

ลำโพงเปล่าต้องต่อผ่านวงจรขับ/โมดูลขยายเสียงที่เหมาะกับค่าโอห์มและกำลังของลำโพง ไม่ต่อตรง GPIO2 เพราะขา GPIO เป็นขาสัญญาณ ข้อมูล GPIO และค่าทางไฟตรวจได้จาก [เอกสาร ESP32-S3 ของ Espressif](https://www.espressif.com/sites/default/files/documentation/esp32-s3_datasheet_en.pdf)

ตอนนี้ `include/config.h` ตั้ง `SOUND_DRIVER_CONNECTED = false` ไว้ จึงยังไม่มีเสียงจริง แต่จอและปุ่มทำงานได้ครบ ไม่ต้องรออุปกรณ์เสียง

เมื่อเพิ่มวงจรขับที่รับสัญญาณ 3.3 V และต่อถูกต้องแล้ว จึงเปลี่ยนค่านั้นเป็น `true` และ Upload ใหม่ เส้นทางคือ GPIO2 → อินพุตวงจรขับ → ลำโพง; การต่อไฟเลี้ยง/กราวด์/เอาต์พุตให้ยึดรุ่นวงจรขับจริง โค้ดสร้างโทนด้วย LEDC ของ Arduino-ESP32 2.0.17 ที่ตรึงเวอร์ชันไว้

## ผลตรวจเดิมก่อนรุ่น 1.5.0 (ประวัติ)

- คอมไพล์ PlatformIO สำเร็จสำหรับ ESP32-S3 / Flash 4 MB; ใช้พื้นที่โปรแกรมประมาณ 304 KB และ RAM คงที่ประมาณ 135 KB รวมภาพพักทั้งจอ ไม่ต้องใช้ PSRAM
- ภาพตัวอย่างเรนเดอร์จาก `include/face.h` ตัวเดียวกับเฟิร์มแวร์ ตรวจข้อความและขอบหน้าปัดที่ 240×240 แล้ว
- ทดสอบการกรองปุ่มเด้ง กดสั้น กดค้าง การไม่กดซ้ำตอนปล่อย และตัวนับเวลาวนรอบบนคอมผ่าน
- BME680 อ่านอุณหภูมิ/ความชื้น/ความดันจริงและแสดง `--` เมื่อข้อมูลหาย ไม่มีค่า IAQ, SpO₂, เข็มทิศ หรือเปอร์เซ็นต์แบต; ชีพจรและ GPS เพิ่มในโค้ดปัจจุบันแล้ว แต่ยังไม่ได้ทดสอบชุดเซ็นเซอร์ใหม่กับบอร์ดจริง
- อัปโหลดลง Super Mini จริงที่ COM15 สำเร็จและตรวจ hash ของข้อมูล Flash ผ่าน เครื่องรายงาน Flash 4 MB / PSRAM 2 MB ตั้งเวลาจากคอมได้ (`TIME OK`) และตอบ `BME=live` ต่อเนื่อง
- พบอุปกรณ์ตอบที่ 0x57, 0x18 และ 0x1E ในช่วงตรวจผ่าน USB แต่การตอบที่อยู่ไม่ยืนยันคุณภาพการวัดของแต่ละเซ็นเซอร์
- ยังไม่ได้รับผลยืนยันภาพและการกดปุ่มจากผู้ใช้ที่หน้าเครื่องจริง เสียงยังปิดตามการต่อแบบลำโพงเปล่า

ใช้ [ไดรเวอร์ GC9A01A ของ Adafruit](https://github.com/adafruit/Adafruit_GC9A01A) และ [การตั้งค่าบอร์ด ESP32-S3 ใน PlatformIO](https://docs.platformio.org/en/latest/boards/espressif32/esp32-s3-devkitc-1.html) โดยปรับ Flash เป็น 4 MB สำหรับ Super Mini
