ปรับจาก Revision A ให้ใช้สัญลักษณ์มาตรฐาน KiCad สำหรับไฟ 3.3V, กราวด์, ปุ่มกด, ลำโพง, เซลล์แบตเตอรี่, คอนเน็กเตอร์ และเสาอากาศ ลากบัส I²C ต่อถึงโมดูลทั้งสี่ พร้อมจุดต่อและเส้นข้าม ส่วนบอร์ดสำเร็จรูปยังเป็นสัญลักษณ์โมดูลตามขาที่ใช้จริง รูปชิปและหน้าปัดภายในสัญลักษณ์เป็นเครื่องหมายบอกหน้าที่ของโมดูล

เปิด `KU_Watch.kicad_pro` ใน KiCad แล้วเปิด `KU_Watch.kicad_sch` ได้ทันที มีสัญลักษณ์ฝังในไฟล์และไลบรารี `KU_Watch.kicad_sym` พร้อม `sym-lib-table` สำหรับแก้ไขต่อ

ไฟล์นี้เป็น **แบบเชื่อมต่อระหว่างโมดูล** บนกระดาษ A3 ไม่ใช่วงจรภายในชิปหรือแบบ PCB พร้อมผลิต เลขขาในสัญลักษณ์เป็นชื่อหน้าที่ เช่น GPIO8, SDA, VCC ไม่ใช่ลำดับรูบนบอร์ด ไม่มีการกำหนด footprint ที่ยังไม่ทราบขนาดจริง

## อุปกรณ์ในแบบ

| อ้างอิง | อุปกรณ์ | สถานะ |
|---|---|---|
| U1 | ESP32-S3 Super Mini | บอร์ดหลัก อ่านเซ็นเซอร์และรับ GPS |
| DS1 | จอกลม GC9A01(A) 240×240 | ขาสัญญาณตามโค้ดปัจจุบัน |
| U2 | BME680 | I²C 0x76; CS ต่อ 3V3, SDO ต่อ GND |
| U3 | MAX30102 breakout | I²C 0x57; ต้องเป็นโมดูลที่รองรับไฟและสัญญาณตามแบบ |
| U4 | GY-51 ตามชื่อในโค้ด | อ่าน ACC 0x18 / MAG 0x1E; ยังไม่ยืนยันชิปจริง |
| U5 | INA226 | โค้ดตรวจ ACK 0x40 เท่านั้น; เว้นทางวัดกระแสไว้ |
| U6 | ATGM336H พร้อมเสาอากาศ | ต่อกับ Super Mini ตามที่ผู้ใช้ยืนยัน; ขา UART เป็นข้อเสนอ |
| AE1 | เสาอากาศ GNSS ที่มากับชุด | ต่อช่องเสาอากาศของ U6; ขา ANT ในแบบแทนช่องต่อบนโมดูล ไม่ใช่เลขขาชิป |
| U7 | ESP32-S3-Touch-LCD-2.1 | บอร์ดจออีกตัว สื่อสาร ESP-NOW สองทาง; จ่ายไฟผ่าน USB ของตัวเองในแบบนี้ |
| SW1 | ปุ่มกดเมนู | ปกติเปิด; กดแล้วต่อ GPIO4 ลง GND |
| J1 | จุดสำรองเข้าวงจรขับเสียง | เป็นจุดต่อเชิงหน้าที่ ไม่ได้เพิ่มวงจรขับเป็นอุปกรณ์ที่มีแล้ว |
| LS1 | ลำโพงสองสาย | แยกไว้จนกว่าจะระบุรุ่นวงจรขับ |
| BT1 | แบตเตอรี่ 582535, 3.7V, 600mAh, 3 สาย | ใช้กับ Super Mini ตามที่ผู้ใช้ยืนยัน; ยังไม่ต่อทางไฟ |
| J2 | สาย/ขั้วต่อ 3 สายของแบตเตอรี่ | เว้นทุกขาไว้; หมายเลข 1–3 เป็นตำแหน่งในสัญลักษณ์ ยังไม่ใช่ผังขั้วต่อจริง |

ไม่มีโมดูล SD เดิมในแบบนี้

## ขาต่อตามโค้ด

| GPIO ของ Super Mini | ปลายทาง |
|---|---|
| 10 | จอ SCK / SCL |
| 11 | จอ MOSI / DIN / SDA |
| 6 | จอ CS |
| 7 | จอ DC |
| 5 | จอ RST |
| 8 | SDA ของ BME680, MAX30102, GY-51, INA226 |
| 9 | SCL ของ BME680, MAX30102, GY-51, INA226 |
| 4 | ปุ่มกดไป GND; ใช้ INPUT_PULLUP |
| 2 | สำรองสัญญาณไปวงจรขับเสียง; ปัจจุบันปิดและเป็น input |

อ้างอิง `include/config.h` และ `src/main.cpp` ไม่ใช้ข้อความ GPIO1 ที่ยังหลงเหลืออยู่ในคู่มือรุ่นเก่า

## ส่วนที่เสนอใหม่: GPS

- GPS TXD → Super Mini GPIO12 (รับข้อมูล)
- GPS RXD ← Super Mini GPIO13 (ส่งคำสั่ง)
- เสนอให้ใช้ไฟ 3.3V ที่ผ่านการควบคุมแรงดันแล้ว และ GND ร่วมกับ Super Mini
- ต้องตรวจว่าโมดูล Super Mini ตัวจริงนำ GPIO12/13 ออกมาใช้งาน และโมดูล GPS ตัวที่ซื้อรองรับ VIN 3.3V รวมถึงตรวจลำดับขาจากตัวโมดูลจริงก่อนต่อ
- PPS เว้นไว้ และใช้เสาอากาศที่มากับชุดผ่านช่องต่อของโมดูล
- UART/GPS ยังไม่ได้เพิ่มในเฟิร์มแวร์ และยังไม่กำหนด baud rate เพราะ ATGM336H มีหลายรุ่นย่อย

## ระบบแบตเตอรี่ยังไม่กำหนดวงจร

ผู้ใช้ยืนยันให้แบตเตอรี่อยู่ฝั่ง Super Mini ในแบบจึงแสดง BT1 ฝั่งนี้ด้วยสัญลักษณ์เซลล์แบตเตอรี่มาตรฐาน ขั้ว +/− แสดงหน้าที่ของเซลล์เท่านั้น ยังไม่ได้จับคู่กับสายจริง ส่วน J2 แทนสาย/ขั้วต่อสามสาย โดย **ทั้งสามสายยังไม่เชื่อมกับรางไฟหรือ GND** หมายเลข 1–3 ไม่ได้ยืนยันสี ลำดับขั้ว บวก/ลบ หรือหน้าที่สายที่สาม

กรอบเส้นประระบุสิ่งที่ต้องออกแบบต่อ: การชาร์จ การป้องกันแบตเตอรี่ การควบคุมแรงดัน และการจัดการเมื่อเสียบ USB พร้อมแบตเตอรี่ กรอบนี้เป็นข้อความกำกับ ไม่ใช่อุปกรณ์ที่เลือกแล้วหรือวงจรไฟฟ้าสำเร็จ ต้องทราบหน้าที่สายที่สาม ขั้วแบตเตอรี่ รุ่นบอร์ด Super Mini และงบกระแสรวมก่อนเลือกวงจร

ไฟ `+3V3` ในแบบมาจากตัวควบคุมแรงดันของบอร์ด Super Mini เมื่อจ่ายไฟผ่าน USB-C เพื่อใช้เป็นแบบทดสอบ ห้ามนำแบตเตอรี่ดิบต่อกับราง 3V3 โดยอาศัยภาพนี้

## จุดที่เว้นไว้โดยตั้งใจ

- ขา BL/BLK ของจอ: บางโมดูลมีวงจรแบ็กไลต์ต่างกัน ต้องตรวจโมดูลจริงก่อนต่อ
- INA226 IN+/IN-: ยังไม่เลือกตำแหน่งวัดกระแส ค่าชันต์ และการต่อทางไฟ จึงยังใช้วัดแบตเตอรี่ไม่ได้
- ลำโพง: ยังไม่ทราบค่าโอห์ม กำลัง และรุ่นวงจรขับ; ไม่มีการต่อลำโพงเปล่ากับ GPIO2
- I²C pull-up: ต้องตรวจตัวต้านทานที่มีอยู่บนโมดูลก่อนเพิ่ม ไม่ได้เติมค่าที่เดาขึ้นมา
- MAX30102 ในแบบหมายถึง breakout ที่มีวงจรไฟเลี้ยงเหมาะสม ไม่ใช่ชิป MAX30102 เปล่า
- บอร์ดจอ 2.1 นิ้วมีไฟเลี้ยงของตัวเอง ไม่มีสายสัญญาณหรือกราวด์เชื่อมสองบอร์ดสำหรับ ESP-NOW; ต้องใช้ช่องสัญญาณวิทยุเดียวกัน
- การรับส่ง ESP-NOW และคำสั่งจากจอใหญ่เป็นแผน ยังไม่ได้เพิ่มในโค้ด

## การตรวจไฟล์

ใช้ KiCad CLI 10.0.6 โหลด บันทึกเป็นรูปแบบปัจจุบัน ส่งออก PDF / SVG / netlist และตรวจ ERC พร้อมตรวจ netlist เทียบ GPIO จากโค้ด ดูผลใน `erc.rpt` และ `validation.txt`

ERC ตรวจการเชื่อมต่อตามสัญลักษณ์ที่กำหนดเท่านั้น ไม่ได้ยืนยันรุ่นฮาร์ดแวร์จริง การเลือกวงจรจ่ายไฟ หรือความพร้อมผลิต PCB ขาที่รอต่อถูกระบุ no-connect อย่างชัดเจน จึงไม่ถือเป็นการออกแบบส่วนเหล่านั้นเสร็จแล้ว
