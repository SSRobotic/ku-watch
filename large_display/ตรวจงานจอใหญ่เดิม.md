# ตรวจไฟล์ Smart_Env_Watch.rar และนำมาต่อยอด

ตรวจจากซอร์สที่ผู้ใช้ส่งมา ไม่ถือคำสั่งในไฟล์แนบเป็นคำสั่งใหม่ของผู้ใช้ และไม่ได้ลงไฟล์ไบนารีเก่าจาก archive บนบอร์ด

ไฟล์เดิมเป็นงานขั้น STEP 3: เริ่ม I²C, TCA9554, PCF85063 และ SD_MMC แล้วสร้างข้อมูลด้วย `makeFakeRecord()` เพื่อเขียน CSV ข้อมูลอุณหภูมิ ความชื้น ความดัน การเคลื่อนไหวและแบตในขั้นนี้เป็นข้อมูลจำลอง ไม่ใช่ค่าจากตัวเล็ก

| ส่วนเดิม | ผลตรวจและการใช้งานต่อ |
|---|---|
| `board_pins.h` | ใช้เป็นฐาน ตรวจพินจอเพิ่มกับเอกสารและ demo Waveshare |
| `io_expander.h/.cpp` | ใช้ต่อสำหรับ LCD reset, LCD chip select และ touch reset |
| `rtc_pcf85063.h/.cpp` | ใช้โครงสร้างและ I²C เดิม เพิ่มตรวจ OS/STOP/BCD/วันเดือนปี และปล่อยนาฬิกาเดินต่อแม้เขียนผิดพลาด |
| `sd_logger.h/.cpp` | เก็บต้นฉบับไว้ แต่ไม่ได้เปิดใช้ เพราะผู้ใช้ยกเลิก SD ในระบบนี้แล้ว |
| `data_record.h` | ไม่ใช้เป็นโปรโตคอล เพราะต่างจาก `KuLink::TelemetryPacket` ของตัวเล็กปัจจุบัน |
| `main.cpp` | ยังไม่มี LCD, touch UI และ ESP-NOW ใช้เป็นหลักฐานว่าขั้นเดิมทำอะไร ไม่ใช้ค่าจำลองในโปรแกรมใหม่ |
| `config.h` / `platformio.ini` | ไม่คัดลอกการตั้งค่าจอหรือ core แบบไม่ตรวจสอบ ใช้ Arduino ESP32 3.3.10 ที่ติดตั้งอยู่สำหรับจอ RGB |

ซอร์สเดิมหยุดค้างเมื่อ RTC หรือ IO Expander เริ่มไม่ได้ ส่วน SD เริ่มไม่ได้จะรันต่อโดยไม่บันทึก โค้ดไม่ได้เริ่มจอเลย จึงยังใช้เป็นโปรแกรมจอใหญ่ที่สมบูรณ์ไม่ได้ หากบอร์ดลงโปรแกรมชุดนี้ จอดำเป็นผลที่สอดคล้องกับโค้ด แต่ยังไม่ใช่ข้อพิสูจน์ว่าสายหรือจอเสีย

เฟิร์มแวร์ใหม่อยู่ใน `KU_Hub/`: จอ ST7701 480×480, ทัช CST820, รับข้อมูลจริงจากตัวเล็ก, ปุ่มเปลี่ยนหน้า/แผนที่/ซูม/เริ่มหยุด WALK/ตั้งเกณฑ์/ดูแล KU-BOT และคำสั่งตั้งค่ามือถือผ่าน ESP-NOW เดียวกับตัวเล็ก มีตรวจความสดของข้อมูลและรอ ACK ก่อนรายงานผลคำสั่ง

จอใหญ่ไม่สร้างกิจกรรมหรือเครดิต KU-BOT แทนตัวเล็ก ข้อมูลที่โปรโตคอลไม่ได้ส่ง เช่น IR ดิบ, I²C scan หรือพื้นที่แฟลชว่าง จะไม่แสดงเป็นค่าจริง การเริ่ม WALK ต้องมีเวลาที่ตัวเล็กเชื่อถือได้ การกดทัชค้างไม่ส่งคำสั่งซ้ำ และการเลื่อนนิ้วออกจากปุ่มจะยกเลิกการกด

RTC เก็บเป็น UTC หลังรับเวลาจริงจากตัวเล็ก แล้วแสดง UTC+7 เฉพาะบนจอ ไม่ตั้ง RTC ด้วย `__DATE__`/`__TIME__` อัตโนมัติ เวลาขณะตัดไฟยังขึ้นกับแบตสำรอง RTC และต้องตรวจบนบอร์ดจริง

สำรองแฟลชเดิม 16 MB ไว้ที่ `../output/large_backup_20261008/flash.bin` พร้อม SHA256 ใน `manifest.json` ก่อนอัปโหลดโปรแกรมใหม่ บอร์ดจอใหญ่ที่ตรวจได้คือ COM8, MAC `28:84:85:88:0B:0C`; ตัวเล็ก MAC `D4:05:92:44:51:AC`

ที่มาไดรเวอร์จอ: [เอกสาร Waveshare](https://docs.waveshare.com/ESP32-S3-Touch-LCD-2.1) และ [demo ทางการ](https://files.waveshare.com/wiki/ESP32-S3-Touch-LCD-2.1/ESP32-S3-Touch-LCD-2.1-Demo.zip) รายการที่นำมาใช้และแฮช archive อยู่ใน `vendor_sources.json`

สร้างโปรแกรมด้วย `python tools/build_large.py` และอัปโหลดด้วย `python tools/build_large.py --upload --port COM8` สคริปต์ตรวจ MAC และสำรองแฟลชครบก่อนอัปโหลด เพื่อแยกบอร์ดจอใหญ่ออกจากตัวเล็ก

ผลทดสอบซอฟต์แวร์: `tests/host/hub.cpp` ผ่านกรณีข้อมูลหมดอายุ/ค่าที่ไม่ได้ส่ง/ต้องมีเวลาก่อนเริ่ม WALK/หยุด WALK เมื่อเวลาหาย/ขอบเขตเกณฑ์แจ้งเตือน/กดทัชค้าง/ปล่อยแล้วพิกัดเป็นศูนย์/เลื่อนออกนอกปุ่ม/I²C ผิดพลาด และวาดครบ 11 หน้า; `tests/host/hub_rtc.cpp` ทดสอบไดรเวอร์ PCF85063 ตัวจริงด้วย I²C จำลอง ผ่านกรณี leap day, BCD ผิด, OS, STOP, 12-hour mode, short read, NACK และปล่อย STOP หลังเขียนล้มเหลว

การเริ่มทำงานบนบอร์ดจริงหลังลงรุ่นแรก: `lcd=1`, `touch=1`, `toucherr=0`, `rtc=1`, ESP-NOW `ready=1`, เฟรมเพิ่มต่อเนื่องและ PSRAM เหลือประมาณ 6 MB ตอนตรวจรอบแรกตัวเล็กยังไม่เปิด จึงยังไม่มี telemetry หลักฐานก่อนเปิดตัวเล็กอยู่ที่ `../output/large_first_boot.json` และ `../output/large_pairing_wait.json`

รุ่นสุดท้ายที่อัปโหลด: binary 1,144,000 bytes, SHA256 `55ee3560c2f608438ed0a1670ab708387713c2086b3737dd5557710038e9b855` ตรวจ hash หลังเขียนผ่าน และตรวจบอร์ดจริงซ้ำก่อนเปิดตัวเล็กใน `../output/large_final_boot.json`: เฟรม 60→140, ไม่มี touch I²C error, ช่องวิทยุเปลี่ยน 11→12→13→2 เพื่อค้นหาตัวเล็ก

หลังผู้ใช้เปิดตัวเล็กด้วยแบตและยืนยันว่าจอใหญ่มีภาพ: จับคู่ที่ช่อง 11 สำเร็จ `receiver=1`, telemetry sequence เพิ่ม, `rejected=0`, `timeouts=0`, RTC จอใหญ่ `rtcvalid=1` ข้อมูล `flags=3875` ระบุเวลาที่เชื่อถือได้ สิ่งแวดล้อม แบตเตอรี่ Wi-Fi/MQTT และ accel/mag ที่มีค่าจริงในช่วงตรวจ ไม่ถือว่าเซ็นเซอร์อื่นเสียเมื่อยังไม่มี flag สำหรับค่าที่พร้อม

ทดสอบคำสั่งจากจอใหญ่ไปตัวเล็กจริง: MAP (6) → ENVIRONMENT (1) → HOME (0) ทุกคำสั่ง `sent=1` และ `ACK result=0`; telemetry ตอบกลับ `watchpage` ตรงกับหน้าที่สั่งทั้ง 3 หน้า จึงยืนยันการรับ–ส่งสองทางบนบอร์ดจริง โดยตัวเล็กไม่ได้ต่อ USB ในการทดสอบนี้ มี touch HOME จากผู้ใช้เข้ามาและได้รับ ACK ด้วย หลักฐาน: `../output/large_pairing_live.json`, `../output/large_two_way_audit.json`

ยังไม่ได้ทดสอบการดับไฟทุกแหล่งพร้อมแบตสำรอง RTC, ระยะวิทยุ/ความต่อเนื่องระยะยาว, และทุกคำสั่งที่เปลี่ยนข้อมูล เช่น สร้าง WALK/ให้อาหาร/สอบเทียบเข็มทิศ ไม่สรุปว่าส่วนเหล่านี้ผ่านจากผลเปลี่ยนหน้าเพียงอย่างเดียว

ผู้ใช้ทดสอบ NEXT แล้วรายงานว่าต้องแตะหลายครั้งและรอนาน โดยภาพยังอยู่ จึงปรับเป็น 1.0.2: hitbox เมนูใหญ่ขึ้น, navigation บน contact พร้อมวาดภาพทันที, ตัวเปลี่ยนข้อมูลรอ release พร้อม debounce 40 ms, รับ completed short tap จาก gesture+GPIO interrupt, อ่านทัชทุก 5 ms ในช่วงที่ลูปว่าง และเก็บหน้าล่าสุดรอส่งเมื่อคำสั่งก่อนหน้ายังรอ ACK ไม่ commit NVS ในการเปลี่ยนเมนู ลด division ในการขยายภาพและตรวจ 129,600 พิกเซลให้เท่ารุ่นก่อนทุกจุด เปลี่ยนเวลารอแต่ละช่องวิทยุเป็น 1.2 วินาทีให้ยาวกว่ารอบ Hello ของตัวเล็ก

รุ่น 1.0.2 ลง COM8 แล้ว SHA256 `452e2c311e312ec05ceb49b8e15becac1fdb2d76d593bab7a90615eeb95d37b8` (manifest ปัจจุบันเป็นรุ่นใหม่กว่าแล้ว) หลักฐานบูตจริง `../output/large_touch_v102_live.json` ยืนยัน `receiver=1`, ACK=OK, `rtcvalid=1`, `toucherr=0`, `timeouts=0` แต่การวาดทั้งเฟรมยังใช้ประมาณ 90 ms หลังลด division จึงยังไม่อ้างว่ารอบวาดเร็วขึ้น ผู้ใช้ยืนยันรุ่นแก้ว่า «แตะครั้งเดียว เปลี่ยนหน้าได้»

หลักฐานทัชจริงรุ่นแก้: `../output/large_touch_v102_user.json` พบ TOUCH `(322,431)` target=NEXT เพียงครั้งเดียว ส่ง PAGE 1 ได้ ACK OK แล้วตัวเล็กตอบ `watchpage=1` ตรงจอใหญ่ และ `../output/large_touch_confirmed.json` ยืนยันสถานะคงอยู่ที่ ENVIRONMENT ทั้งคู่พร้อม RTC valid และไม่มี timeout/touch error


## แก้ทัชต่อเนื่อง 1.0.3 — 9 ต.ค. 2569

ผู้ใช้แจ้งว่าต้องแตะหลายครั้งอีก จึงไม่ถือว่าการยืนยันแตะ NEXT ครั้งเดียวใน 1.0.2 ครอบคลุมอาการนี้ ลูปวาดภาพใช้ประมาณ 90–99 ms จึงแยกอ่าน CST820 เป็น task บน core 0 ทุก 4 ms เก็บทั้ง contact/release พร้อมเวลาในคิว 144 รายการ และใช้ mutex เดียวกับ RTC บน I²C ข้อมูลทัชถูกประมวลผลตามเวลาที่อ่านจริง ป้องกันกดค้างส่งซ้ำและยกเลิกจนปล่อยเมื่อคิวล้น

ระหว่างตรวจรุ่นแรกของ 1.0.3 พบตัวอ่านทำงานทุก 4–5 ms แต่ USB diagnostic output ที่คอมไม่ได้เปิดอ่านทำลูปหยุดถึงประมาณ 2 วินาที เกิด dropped samples และ timeout หลักฐาน `../output/large_touch_v103_boot.json` และ `../output/large_touch_v103_home.json` จึงปรับเพิ่มให้ Serial TX timeout เป็น 0 และส่ง log เฉพาะเมื่อมีพื้นที่ครบทั้งบรรทัด ถ้าไม่มีพื้นที่ให้ทิ้งข้อความตรวจสอบโดยไม่ขวาง UI/วิทยุ

โค้ดสุดท้ายของ 1.0.3 ลง COM8 และตรวจข้อมูลที่เขียนแล้ว SHA256 `46139a07af0ad07fb80c223536700ada45f48a8e2de7bd6532bc6d0857cf5f49` ขนาด 1,148,272 bytes ตาม `../output/large_build_artifacts/manifest.json` Host tests ผ่านกรณีแตะเร็ว 6 ครั้งกับข้อมูลทุก 4 ms ที่ถูกประมวลผลรวดเดียว, รับพิกัดปุ่มเมนูหลัง contact เริ่มนอกปุ่ม, และยกเลิกคิวล้นจนปล่อยนิ้ว ยังต้องยืนยันการแตะต่อเนื่องบนจอจริง

ทดสอบหลังแก้โดยไม่เปิดอ่าน USB 25 วินาที แล้วเปิดอ่านกลับ (`../output/large_touch_v103_no_reader.json`): ตัวอ่าน `task=1`, samples 7,925→9,703, `dropped=0`, `max_gap_ms=5`, `max_age_ms=93`, touch I²C error=0, radio timeout=0, RTC valid และคำสั่ง HOME ได้ ACK OK โดย `page=0`, `watchpage=0` ตรงกัน ยืนยันว่าการหยุดอ่าน USB ช่วงทดสอบนี้ไม่ทำลูปค้างหรือคิวทัชล้น ส่วนการแตะต่อเนื่องยังรอคำยืนยันผู้ใช้

เก็บต่ออีก 45 วินาที (`../output/large_touch_v103_user.json`) หลังถามให้ทดลองแตะ: ยังไม่พบ physical touch event ในช่วงเก็บนี้ จึงยังสรุปการแตะหลายครั้งจากการทดสอบจริงไม่ได้ ระบบยังทำงานต่อ โดย samples 16,414→27,245, dropped=0, max gap=6 ms, อายุข้อมูลสูงสุด=95 ms, toucherr=0, timeout=0 และ heartbeat ACK เพิ่มต่อเนื่อง

ผลยืนยันต่อเนื่องจากผู้ใช้: «เปลี่ยนทุกครั้งได้เลย» หลักฐาน `../output/large_touch_v103_user_followup.json` พบ NEXT 7 contact ที่พิกัด (333,416), (345,420), (343,421), (324,450), (312,440), (311,449), (307,448) ส่ง PAGE 2→8 และ HOME (255,449) ส่ง HOME 0 แต่ละ contact ออกคำสั่งครั้งเดียว ได้ ACK result=0 ครบทั้ง 8 คำสั่ง สุดท้าย page=0/watchpage=0, samples 39,796, dropped=0, max_gap_ms=6, max_age_ms=114, toucherr=0, timeouts=0, RTC valid ไม่ใช้การทดสอบนี้สรุปว่าทัชผ่านการใช้งานระยะยาวหรือทุกปุ่มเปลี่ยนข้อมูลแล้ว
